# 数据补全方案 V2 —— 每日增量累积体系（2026-08-25 深夜实测修订）

> 修订背景：用户决定「分钟/期货/转债/资金流/北向也补」，且已有每日 18:00 计划任务（QuantBacktestDataSync）持续跑。
> 策略从"一次性回填"升级为"**历史回补 + 每日增量累积**"双轨。
> 本版全部结论为本机逐项实测（curl 直连验证），非推测。

## 一、V2 实测探测结果汇总

### 关键修正
- **akshare 整体不可用**（走东财域名，本机被限流），所有采集改为 curl 直连新浪/腾讯/东财原始接口。
- **腾讯 mkline 已迁移**：`web.ifzq.gtimg.cn/appstock/app/kline/mkline` 返回 301 到不存在的 web3 主机；
  改用 `ifzq.gtimg.cn/appstock/app/kline/mkline`（实测 640 根 m5 正常）。但新浪 1023>640 更优，分钟主力用新浪。

## 二、新库表设计（追加到 stock_data.db）

```sql
-- 分钟线（股票+ETF 共用，5 分钟粒度基础数据；60/30/15 由 5m 聚合或单独存）
CREATE TABLE IF NOT EXISTS stock_minute_hist (
    stock_code TEXT NOT NULL,          -- 6位纯代码（含基金）
    bar_time  TEXT NOT NULL,           -- 'YYYY-MM-DD HH:MM' （5m 收盘时刻）
    open REAL, high REAL, low REAL, close REAL,
    volume REAL,                        -- 股
    PRIMARY KEY (stock_code, bar_time)
) WITHOUT ROWID;

-- 期货
CREATE TABLE IF NOT EXISTS futures_daily (
    symbol TEXT NOT NULL,              -- 'RB0' 主连 / 具体合约
    trade_date TEXT NOT NULL,
    open REAL, high REAL, low REAL, close REAL, volume REAL, hold REAL,
    PRIMARY KEY (symbol, trade_date)
) WITHOUT ROWID;
CREATE TABLE IF NOT EXISTS futures_minute5 (
    symbol TEXT NOT NULL, bar_time TEXT NOT NULL,
    open REAL, high REAL, low REAL, close REAL, volume REAL,
    PRIMARY KEY (symbol, bar_time)
) WITHOUT ROWID;

-- 可转债
CREATE TABLE IF NOT EXISTS cb_daily (
    cb_code TEXT NOT NULL, trade_date TEXT NOT NULL,
    open REAL, high REAL, low REAL, close REAL, volume REAL, amount REAL,
    PRIMARY KEY (cb_code, trade_date)
) WITHOUT ROWID;
CREATE TABLE IF NOT EXISTS cb_minute5 (
    cb_code TEXT NOT NULL, bar_time TEXT NOT NULL,
    open REAL, high REAL, low REAL, close REAL, volume REAL,
    PRIMARY KEY (cb_code, bar_time)
) WITHOUT ROWID;

-- 资金流（尽力而为：受东财风控限制，能攒多少算多少）
CREATE TABLE IF NOT EXISTS money_flow_daily (
    stock_code TEXT NOT NULL, trade_date TEXT NOT NULL,
    main_net REAL, main_pct REAL, huge_net REAL, super_net REAL, big_net REAL, mid_net REAL, small_net REAL,
    PRIMARY KEY (stock_code, trade_date)
) WITHOUT ROWID;
```

## 三、任务重排（V2）

### P0-P2 维持不变（指数/high-low/ETF 回填，先做）
见《数据补全方案.md》原版。

### P5 分钟线滚动累积体系（新增，核心）
**历史起点**：今天起每天收盘后跑 → 5 分钟线从今日起永久累积；60 分钟线直接回补一整年。
**每日增量脚本** `scripts/sync_minute_hist.py`：
1. 读 `trade_calendar` 取最近 N 个未覆盖交易日（断点续传：查 stock_minute_hist 每 code 的 MAX(bar_time)）
2. 全市场 5534 只 × sina scale=5 datalen=1023（每请求覆盖 ~21 天，日常只需 datalen=48×N）
   - 3~4 并发 + 300ms 间隔，预计 8~12 分钟/天
3. INSERT OR IGNORE 写入；行数校验（当日应有 ~48×5534≈26.6 万行）
4. 挂到现有计划任务：18:05 执行（在 QuantBacktestDataSync 之后）
**首次回补**：跑一轮 datalen=1023 即得近一个月 5m 历史 + 单独跑 scale=60 得一年 60m 历史。

### P6 期货回补与累积（新增）
- 一次性：新浪 getDailyKLine 拉 ~70 个活跃品种主连（RB0/CU0/I0/M0/TA0...清单内置）2009→今
- 每日增量：同接口只取最新 2 根；5 分钟线 getFewMinLine type=5 count=1023（15 天窗口，每日跑即无缝）
- 预计解锁 65 个期货策略中的大部分（趋势/动量/双均线类）；套利类需要多合约价差的用具体合约代码同样可拉

### P7 可转债回补与累积（新增）
- 一次性：转债清单（东财 CB 列表接口或集思录公开页解析，待实现时选可用者）→ 逐只 push2his klt=101 全史回填
- 每日增量：现存转债 ~500 只 × 1 请求，低频 2s/次 ≈ 17 分钟
- 分钟线：仅对策略实际引用的转债做 5m 累积（东财风控限制下不全市场扫）
- 解锁 38 个转债策略中的大部分（摊大饼/双低轮动类）

### P8 资金流尽力而为（新增，低优先级）
- 东财 fflow 风控极严（本次探测即被封）。方案：单线程、≥12s/次、失败退避 30 分钟、每日只轮转一部分股票（分片，每周覆盖全市场一遍）
- 明确声明：资金流数据完整性无法保证，相关策略报告标注"资金流数据不完整"

### P9 北向资金 —— 最终否决（新增）
- **非本地问题，是数据源消亡**：2024-08-16 起交易所不再披露北向单日净买入（实测 kamt 序列值全 0）
- 涉及北向的策略（普查中约 10+ 个）统一按「数据源已停发，策略不可复现」否决，写明依据

## 五、执行顺序（更新后）

```
第 1 天：P0 指数 → P1 高低价+分红+涨跌停 → P2 ETF 日线        （解锁日线类 ~255+250 个）

```

## 六、风险与守则（沿用+新增）

- 沿用：断点续传、只插不改、行数守恒、抽样核验、后台 5 分钟强杀→run_in_background 分批
- 新增①：新浪/腾讯接口温和（免登录不限严），东财接口凶狠（fflow 已实测封禁）——东财通道一律 ≥10s 间隔+退避
- 新增②：分钟数据从 2026-08-25 起才有，任何依赖更早分钟史的策略在 S1 审查时就地否决并注明
- 新增③：期货主连换月拼接未处理平滑（后复权拼接法留待 P6 实现，先用原始主连价，报告声明换月跳空影响）
