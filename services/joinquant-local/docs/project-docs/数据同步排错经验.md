# 数据同步排错经验（2026-08-12）

> 记录一次 baostock 服务端故障 + 每日选股同步踩坑全过程的**根因、修复与教训**，避免重复踩坑。

## 背景

2026-08-12 每日选股时，本地 `stock_daily` 停在 08-07（滞后 2 个交易日）。排查发现 sync_quick.py 报"跳过同步"，但 baostock 实际已发布 08-10/08-11 数据——**是探针 bug 误报**，随后 baostock 服务端又持续故障，最终改用**腾讯/新浪回填**补全数据。

---

## 坑 1：`sync_quick.py` 探针被 baostock stdout 干扰 → 误报"跳过同步"（根因）

**现象**：`check_data_fresh` 输出 08-07（滞后），`sync_quick.py` 却打印"跳过同步"，数据始终没更新。

**根因**：baostock 的 `login()`/`logout()` 会向 **stdout** 打印 `login success!` / `logout success!`。旧探针用 `lines[-1]`（取输出最后一行）解析结论，拿到的是 logout 的 `logout success!`，落到兜底 else 分支 → 即使有数据也误判"跳过"。

**修复**：探针所有结论行加 `PROBE_OUT:` 前缀，`main()` 只取最后一个带该前缀的行：
```python
out = next((l for l in reversed(lines) if l.startswith('PROBE_OUT:')), '')
out = out[len('PROBE_OUT:'):] if out else ''
```

**教训**：**子进程/库的结论解析用唯一前缀标记，不要取"最后一行"**——任何库都可能在 stdout 上打印日志（baostock 就是典型）。

---

## 坑 2：探针只查"最新交易日" → 漏同步昨天已发布的数据

**现象**：修好坑 1 后，探针报"2026-08-12 数据未发布，跳过"——但 08-10/08-11 明明可同步。

**根因**：探针只查 `new_days[-1]`（最新交易日，即今天），今天数据 baostock 还未发布 → 误判 NOT_PUBLISHED。而更早的新交易日（昨日/前日）已可同步。

**修复**：探针改为查「本地最新之后**整个区间**」，只要有任一日期返回数据行即可同步（取有数据的最后一天报 READY）：
```python
probe = bs.query_history_k_data_plus("sz.000001", "date,code", start_date=last_local, end_date=today, ...)
avail = [r[0] for r in ... if r[0] > last_local]
print("PROBE_OUT:" + ("READY:" + max(avail) if avail else "NOT_PUBLISHED:" + latest))
```

**教训**：**"有没有新数据"要查区间，不是查单日**；最新交易日（今天）数据常滞后数小时发布，昨天/前天的才是真正可同步的。

---

## 坑 3：baostock 服务端故障的三连表现 + 无超时挂起

**现象**（2026-08-12 早，持续 ~1 小时）：
1. `query_trade_dates` 调用瞬间返回 `error_code=0`，但 **`rs.next()` 迭代永久挂起**（内部 socket 无超时，`socket.setdefaulttimeout(30)` 对其自定义连接不生效）。
2. 连接失败 `[WinError 10057] 由于套接字没有连接……`。
3. login 报 `error_code=10002007 网络接收错误`。

**关键诊断**：间歇性——**独立最小探针多次能通、同步脚本多次挂**。同一 query 并发下探针秒回、sync 挂死 → baostock 按**登录连接**分发的坏连接。无法在进程内检测/超时挂起的 `rs.next()`。

**应对**：写**自动重试驱动**：
- 每轮同步用 `timeout 280` 硬超时包住（进程级，能杀无超时挂起）；
- 挂起/失败 → 杀进程、删残留锁 `data/sync.lock`、**冷却 120~240s** 再重试（避免在坏窗口快速空转打爆服务器）；
- `INSERT OR IGNORE` + done 集合保证**断点续传**（已同步股票自动跳过）；
- 目标达标即停（`daily_stock_pick` 的"完整交易日"= 行数≥4000）。

**教训**：免费数据源服务不稳定时，永远假设会挂起：**进程级硬超时 + 清锁 + 冷却重试 + 断点续传**四件套。

---

## 坑 4：腾讯/新浪回填（baostock 故障兜底方案）

`scripts/backfill_daily_tx_sina.py` —— 逐只拉最近日K，`INSERT OR IGNORE` 补 `stock_daily` 缺失日。全市场 ~5900 只、6 线程并发约 **5~6 分钟**。

**关键口径（易错）**：
- 腾讯 `fqkline` 必须用 **`bfq`（不复权）**：`qfq` 前复权价与存量 CSMAR/baostock（原始价）不一致。bfq 价格与 DB 逐笔核对一致。
- K 线行格式 `[date, open, close, high, low, volume_手]` → volume **手×100=股**，才与 `stock_daily.volume`（股）一致。
- 新浪 `getKLineData` 的 volume 是**股**、无 amount；amount 用 `volume × close` 估算（与真实成交额误差 <1%）。
- 腾讯 K 线接口**不支持批量**（多代码返回 list 报错），只能逐只 + 多线程并发。
- 回填**不写** `trade_calendar` / `index_daily` → 报告 1.1 指数表会为空，用腾讯实时指数替代。
- 回填后应跑一次 `check_data_fresh.py` + 逐票核对收盘价与腾讯实时行情。

---

## 坑 5：回填脚本的 `pre_close` 链式 bug（08-11 全部算错）

**现象**：回填后 600269 08-11 显示 pre_close=3.90（应为 3.94）、中国海油涨跌幅 +7.56%（应为 +5.31%）。

**根因**：`build_rows` 最初只在"非目标日"才更新 `prev_close`，导致目标日 08-11 沿用了 08-07 的 close，而非 08-10 的 close。

**修复**：**每根 K 线处理完都更新 prev_close**（无论是否目标日）：
```python
for day in sorted(bars):
    o, c, h, l, vol = bars[day]
    if day in DATES and prev_close and prev_close > 0:
        rows.append((... c, prev_close, c/prev_close-1 ...))
    prev_close = c   # 关键：每根都更新
```

**教训**：跨日衍生字段（pre_close/涨跌幅/复权）**必须按交易日逐根顺序推导**，不能只在某些分支更新；回填/同步后**必须做数据一致性校验**（本票核对 10 只 top 票与腾讯实时行情全部一致才算过）。

---

## 坑 6：环境限时杀后台进程 → 分批 + 断点续传

- 本环境后台任务约 **5 分钟被强杀**（`0xC000013A Ctrl+C`）；全量增量同步约 40 分钟（遍历全部股票补缺失日）必被中断。
- 方案：`update-daily-baostock.py --max-stocks N --delay 0.05` **分批**，每批跑到正常结束（锁自动释放）再跑下一批；已同步的靠 done 集合自动跳过。
- 被强杀会残留 `data/sync.lock` → 下次 `acquire_lock` 检测到 2 小时内锁直接跳过，**需手动删锁**再续跑。

---

## 结论速查

| 问题 | 一句话解决 |
|---|---|
| 同步误报"跳过" | 探针结论用 `PROBE_OUT:` 前缀解析，别取最后一行 |
| 漏同步昨天数据 | 探针查整个区间而非最新单日 |
| baostock 挂起/失败 | 进程级 timeout + 清锁 + 冷却重试驱动 |
| baostock 持续故障 | `backfill_daily_tx_sina.py` 腾讯/新浪回填（bfq 不复权） |
| pre_close 算错 | 每根 K 线都更新 prev_close，勿只在部分分支更新 |
| 后台被限时杀 | `--max-stocks` 分批 + 断点续传 + 手动清残留锁 |

## 每日选股图文报告 + 因子诊断（2026-08-12 实现要点）

在同步修复后，把每日选股报告升级为**图文兼备 + 因子自诊断**（一~九节），要点与踩坑记录如下。

### 报告结构（脚本生成 一~八，Claude 追加 九）
一 市场概况 → 二 方案+**2.1 因子定义与公式** → 三 top-50 → 四 组合画像 → 五 入选理由 → 六 口径风险 → **七 技术面辅助图** → **八 因子诊断与优化建议** → 九 Claude 亮点点评。

### ① 因子权重与公式进报告
- 直接读 `scripts/factor_registry.json`（因子定义唯一来源）自动渲染：每个因子行的 方向/权重/公式(desc)/数据源 全部来自注册表，**零手工维护**。
- 打分公式显式写出：`综合得分 = Σ wᵢ × 方向ᵢ × z-score(缩尾[1%,99%] 因子ᵢ)`。

### ② 因子诊断与优化（`scripts/optimize_factors.py`）
- **8.1 历史名单追踪**：`daily_stock_pick.py` 每日把 top-N 写 `data/picks_history.json`，次日开始算每期名单至今等权收益 vs 沪深300（停牌不计、分红未计、短期窗口影响小）。首期报告显示"暂无历史"是正常现象。
- **8.2 因子 IC 诊断**：取近 ~55 个交易日，每 5 日一个截面（~10-11 个快照），因子 vs 未来 5 日收益算 **rank IC**（`pandas.Series.corr(spearman)`）；与注册表方向同号且 |IC|≥0.02 判有效。性能：全池 ~5000 只 × 11 快照 × 7 因子，秒级~1 分钟内。
- **8.3 月度权重校验**：复用 `research_panel.pkl` + `validate_daily_schemes.run_config/metrics`，滚动评估当前方案 vs 候选（最近 37 月）。**防过拟合铁律：权重只月度复核、不日更**；仅当候选夏普持续更高才提示微调。
- 踩坑：IC 表头 `%ds` 笔误成 `近11s`——字符串拼接别漏 `%`；逐快照 `fc.get_factors` 对基本面因子会重复查财务表，可接受但注意性能。

### ③ 技术面图（`scripts/chart_strategies.py`）
- matplotlib **Agg 无头后端** + `SimHei` 中文字体（`axes.unicode_minus=False` 防负号乱码）。
- **布林带** = MA20±2σ（`fill_between` 填充）；**海龟通道** = 20 日唐奇安高低轨（滚动 max/min，虚线）。
- **关键坑：存量 baostock 段 `high/low` 全 NULL**——海龟通道直接用 high/low 会 `TypeError: float() NoneType`。必须**用 close 近似 high/low**：`highs = [h if h is not None else close]`。
- 图写 `每日选股/images/`（docs + Obsidian 两处），报告用**相对路径** `![](images/xx.png)` 引用（两处目录结构相同，引用一致）。
- 当日表现条形图：指数涨跌幅用腾讯 `qt.gtimg.cn` 实时接口兜底（`index_daily` 未回填最近两日）。
- 组合净值曲线：组合等权回放用 stock_daily，基准沪深300 用腾讯 `fqkline(bfq)` 补全最近两日（index_daily 缺）。

### ④ 基本面与估值快照（`scripts/fetch_fundamental.py`）
- **实测结论：腾讯/新浪免费财报 JSON 接口不可用**——`proxy.finance.qq.com/.../getMainFinancial` 报 `No dispatch info`、新浪 `CN_FinancialService.getProfitStatement` 报 `Service not valid`。**拿不到营收/净利/ROE 等财报科目 JSON**。
- 落地替代：**估值用腾讯行情实时字段**（已用茅台/工行/招行/五粮液/海油反推验证）：
  - `f[39]=PE_TTM`、`f[46]=PB`、`f[44]=A股市值(亿)`、`f[45]=总市值(亿，含H)`；
  - 财务指标用**已入库的 CSMAR 季度报表**（因子本就在用，口径一致）。
- 交叉校验价值：腾讯 PB 能暴露因子换算 PB 的失真（如中国海油腾讯 PB 2.0 vs 因子估 0.1、中国移动 1.5 vs 0.1）——H 股/大票的市值推算失真，**点评引用以腾讯为准**。
- 注意：腾讯行情是 **gbk** 编码（`urllib` 用 `decode('gbk')`，别用 utf-8 否则名称乱码）。

### 图片/文件双写约定
- `daily_stock_pick.py` 把报告写 docs + Obsidian 两处；图表模块把 PNG 写 `images_dirs[0]` 后 `shutil.copy` 到其余目录。
- 任一联动模块（画图/优化）异常都**降级为提示行**，不阻塞主报告生成（try/except 包裹）。
