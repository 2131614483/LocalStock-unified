# LocalStock Unified 项目介绍

> 本地自用的 A 股行情 + 量化回测一体化桌面软件：同花顺风格界面、免登录、全部数据落本地 SQLite，
> 配套一个聚宽兼容的本地研究 / 回测服务，以及一套 Al Brooks 价格行为 AI 分析服务。



***

## 一、项目定位

LocalStock Unified 是把三件原本分散的东西收敛到同一个工作区后的统一版本：



| 角色                | 说明                                             |
| ----------------- | ---------------------------------------------- |
| **桌面行情软件**        | Electron + React 写的 Windows 桌面应用，同花顺深色风格，红涨绿跌  |
| **本地量化研究 / 回测服务** | Node/Express + Python 引擎，聚宽风格策略 API，浏览器里用      |
| **价格行为 AI 服务**    | 移植自 `PA_Agent_616` 的 Al Brooks 价格行为体系，随桌面端自动启停 |

它**不连云端数据库、不强制登录、不依赖外部行情服务**：行情库是一个本地 SQLite 文件，

实时行情通过东财 / 腾讯 / 新浪多源回退拉取，分析结果与配置全部写在本机。



* 许可证：AGPL-3.0

* 当前桌面端版本：0.2.0

* 运行平台：Windows（打包为 portable exe）

**三条数据流主线：**



1. `stock_data.db` 是唯一权威行情库，桌面端、聚宽服务、pa-agent 三者都读它；pa-agent **只读**。

2. 聚宽服务跑在 `:3000`，桌面端主进程作为 "量化网关" 调用它。

3. pa-agent 端口由操作系统自动分配（`PA_AGENT_PORT=0` + 端口文件回报），桌面端启动时拉起、退出时关闭，

   分析结果经 SSE 流式推回桌面端。

## 三、三大核心组件

### 3.1 桌面端 `apps/desktop`

同花顺风格的 A 股桌面行情软件，也是整个工作区的主入口。

**技术栈：**



* 壳：Electron 37 + electron-vite 3

* 渲染层：React 19 + Zustand 5 + ECharts 5

* 存储：better-sqlite3（同步 API，主进程是唯一 DB 客户端）

* 编辑：CodeMirror（策略代码）

* 打包：electron-builder（Windows portable）

**进程结构（electron-vite 标准三段式）：**



| 进程  | 目录                    | 职责                                                                   |
| --- | --------------------- | -------------------------------------------------------------------- |
| 主进程 | `electron/`           | 建窗口（1360×860 深色）、初始化 SQLite、注册全部 IPC、行情轮询、拉起 Python 子进程              |
| 预加载 | `electron/preload.ts` | `contextBridge` 暴露 `window.api`，所有调用包装成 `ipcRenderer.invoke` Promise |
| 渲染层 | `src/`                | React UI，5 个 Zustand store，无路由靠 `view` 判别联合切页                        |

**IPC 契约：**`shared/types.ts` 是唯一真相源，定义 `WindowApi`；

新增 IPC 必须同步改三处 ——`shared/types.ts`、`electron/preload.ts`、`electron/ipc.ts` 的 handler。

频道命名 `domain:method`：`market:*`、`watchlist:*`、`backtest:*`、`drawings:*`、

`ai:*`、`selection:*`、`monitor:*`、`pa:*` 等。

### 3.2 聚宽兼容服务 `services/joinquant-local`

浏览器里用的本地量化研究 / 回测平台，策略 API 兼容聚宽风格。



* **后端**：Node.js Express + SQLite REST API

* **回测引擎**：`engine/backtest_engine.py`，纯 Python 标准库，`exec()` 注入策略代码

* **前端**：原生 HTML/CSS/JS + Chart.js（无框架），静态文件从项目根目录直出

* **业务库**：`data/backtest.db`（用户 / 策略 / 回测记录 / 成交 / 持仓，百级）

* **行情库**：与桌面端共用 `stock_data.db`

**回测链路：**



```
浏览器 main.js

&#x20; → POST /api/backtest/:id/run

&#x20; → server/index.js 用 execFile 起 Python 子进程

&#x20; → backtest\_engine.py 读 stock\_data.db 执行策略

&#x20; → stdout 输出纯 JSON（120s 超时、50MB 缓冲）

&#x20; → server/db.js 写入 backtest.db

&#x20; → 前端刷新图表
```

> 关键约束：引擎 stdout 必须是
>
> **纯 JSON**
>
> ，策略代码里禁止 
>
> `print()`
>
> ，一律用 
>
> `log()`
>
> ，
> 否则 
>
> `JSON.parse`
>
>  直接失败。

**多因子体系（双轨）：**



* 研究轨：`scripts/` 下 pandas 脚本，系统 Python 3.11 跑，做因子发现与组合迭代

* 生产轨：`engine/factor_calc_stdlib.py` 纯标准库，网页复现同样的因子值

* 两轨共用 `factor_registry.json` 定义，一致性脚本校验偏差 ≤ 0.001

* 约 20 个因子：动量 / 反转 / 波动 / 流动性 / 技术 / 规模 / 价值 / 质量 / 成长

* 无未来函数三铁律：基本面报告期 +4 个月滞后、动量 skip 最近 20 交易日、

  股票池剔除 ST / 涨跌停 / 次新 / B 股 / 北交所 / 金融股

### 3.3 价格行为 AI 服务 `apps/desktop/python/pa-agent`

移植自 `D:\pythonpro\PA_Agent_616` 的 Al Brooks 价格行为体系分析服务。



* **界面**：React 重写（`src/views/PaView.tsx`），核心逻辑跑在 Python 服务里

* **数据**：只读 `stock_data.db`，**无写权限**

* **生命周期**：桌面端启动时拉起、`before-quit` 时关闭，不单独启动

* **端口**：`PA_AGENT_PORT=0` 由系统分配，经端口文件回报，避免抢端口竞态

* **大模型**：配置从桌面端「设置 → AI 后端」读取，随请求体传给服务端；服务端不存密钥

**运行环境自给（可拷贝到没装 Python 的电脑也能跑）：**



1. 优先用自带 venv（`<userData>/pa-agent-venv`）

2. 没有就找本机 Python 建 venv（pip 默认清华源）

3. 都没有才从 GitHub 下载独立 CPython（约 21MB），走 ghproxy 代理优先

**SSE 事件流：**`started / frame_ready / stage_event / stage1_reasoning / stage1_content /`

`stage2_reasoning / stage2_content / prompt / token_update / done / error / closed`。

周期仅 `1d / 1w / 1M`，周 / 月由服务端聚合日线。

## 四、数据层

### 4.1 两个 SQLite 数据库



| 库           | 位置                                      | 客户端               | 内容                                                                                                           |
| ----------- | --------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------ |
| **行情库（权威）** | `data/market/stock_data.db`             | 桌面端、聚宽服务、pa-agent | `stocks`、`stock_daily`（约 1850 万行，bfq 不复权）、`trade_calendar`、`index_daily`、`stock_minute`、`stock_minute_kline` |
| **桌面业务库**   | `app.getPath('userData')/localstock.db` | 仅桌面主进程            | 自选股、设置、K 线缓存、画线与历史、预警规则与事件、AI 审计、选股规则与结果、实时监盘                                                                |
| **聚宽业务库**   | `services/.../data/backtest.db`         | 仅聚宽服务             | 用户、策略代码、回测记录、逐日净值、成交、持仓                                                                                      |

### 4.2 行情库路径解析优先级

桌面端通过设置页「行情库位置」可指定任意位置的库文件，切换后立即生效：



```
设置 marketDbPath（用户界面显式选定）

&#x20; → 环境变量 LOCALSTOCK\_MARKET\_DB

&#x20; → 便携包同目录 data/

&#x20; → exe 同目录 data/

&#x20; → userData/stock\_data.db
```

> 聚宽服务目录里的 
>
> `data/stock_data.db`
>
>  是同一 NTFS 文件的
>
> **硬链接**
>
> ，不占第二份空间；
> 但 electron-builder 重建 
>
> `dist/`
>
>  时
>
> **不要**
>
> 硬链接权威库（曾因此损坏过唯一权威库）。

### 4.3 实时行情多源回退链

所有出站请求过全局串行 Limiter（250ms 最小间隔，队列超 200 丢最旧）。



| 数据                       | 优先级                                                                   |
| ------------------------ | --------------------------------------------------------------------- |
| 实时快照                     | 东财 push2 → （失败 / 空则 60s 冷却）腾讯 [qt.gtimg.cn](https://qt.gtimg.cn)（GBK） |
| 日 / 周 / 月 / 季 K 线        | 本地 `stock_daily`（JS 聚合周 / 月 / 季）→ `kline_cache`（TTL）→ 东财 push2his     |
| 分钟 K 线（1/5/15/30/60/120） | 新浪 `getKLineData` → 腾讯 `mkline`；120 由 60 两两聚合                         |
| 分时                       | 60s 缓存 → 本地 `stock_minute` → 新浪 scale=1 → 东财 trends2                  |
| 盘口五档                     | 仅腾讯（GBK，iconv-lite 解码）                                                |
| 搜索                       | 东财 searchapi（过滤 AStock）                                               |

> 东财分钟 / 季 K 不可靠（会忽略 klt 返回日 K），所以分钟 K 走新浪 / 腾讯，季 K 走本地日线聚合。

## 八、关键设计原则与约束



1. **唯一权威行情库**：`data/market/stock_data.db` 是唯一数据源，不得在其他目录新增独立行情库副本。

2. **pa-agent 只读**：价格行为 AI 服务对行情库只有读权限，不写任何业务表。

3. **IPC 三处同步**：新增 / 修改 IPC 必须同时改 `shared/types.ts`、`preload.ts`、`ipc.ts` handler。

4. **Python stdout 纯净**：回测 / 算法画线子进程的 stdout 必须是机器可解析的 JSON / JSONL，

   禁止额外 `print()`，日志一律走 `log()` 或 stderr。

5. **股票代码归一化**：策略写 `600519.XSHG`，库内键是 6 位 `600519`，引擎 `.split('.')[0]` 提取。

6. **行情库存在幸存者偏差**：Sina/AkShare 只覆盖现存股票，长周期回测收益偏高，近 3–5 年影响小。

7. **UI 风格统一**：全部中文文案、深色主题，红涨绿跌（`--up #f5222d` / `--down #14b143`），

   复用全局类（`.stock-table`、`.chart-box` 等），不写内联样式。

8. **不提交**：数据库、运行状态、密钥、缓存、`node_modules`、打包产物。

9. **改完必跑**：修改桌面端后至少跑根目录 `npm run typecheck` 与 `npm test`；

   改 UI 后还要按视觉测试流程对打包产物截图验证。

10. **不动旧目录**：`D:\pythonpro\desktop\desktop` 与 `D:\pythonpro\聚宽-local` 是历史版本，只读保留。
