# 视觉识别测试清单（界面清单）

> 定位：配合 **visual-test**（Playwright 截图）与 **zhipu-vision**（智谱云端识图）的界面渲染验证清单。图像识别负责 DOM / 像素断言覆盖不到的"画面语义"验证——尤其 ECharts canvas 图表、多栏布局、红涨绿跌着色是否真的画对、画在了对的位置。

## 0. 为什么需要图像识别

- DOM 断言只能确认元素存在；canvas 上的蜡烛/曲线/画线是否**真的渲染**、颜色与布局是否正确，DOM 看不到。
- 现有 spec 已做像素级局部断言（白线亮度、画线前后区域 diff），但**语义级验证**（"这是分时图不是日K""盘口买卖五档齐全""AI 预测列有方向/置信度/理由"）交给视觉模型更高效、更接近人眼判断。

## 1. 前置条件

| 项 | 命令 / 位置 |
|---|---|
| 打包产物 | `npm run build:win` → `dist/win-unpacked/LocalStock.exe`（测试启动的是打包产物，不是 dev server） |
| Playwright 截图 | `npx playwright test scripts/<spec>.spec.js --reporter=list`，截图输出到 `test-results/` |
| 云端识图 | `node ~/.claude/skills/zhipu-vision/zhipu-vision.js "<截图绝对路径>" "检查要求"`（智谱 GLM-4.6V-FlashX，key 自动从 skill 目录 `.env` 加载，无需本地 GPU/Ollama） |
| 数据 | 本地行情库（`data/stock_data.db` 或 userData）；无库时部分界面呈空态，需单独判断"空态是否符合预期" |

## 4. 覆盖情况速查

- **已有专门 spec**：分时/5日/分钟K/季K（`-periods`）、画线（`-drawing`）、分时 AI 标注（`-minute`）、选股（`-selection`）、AI（`-ai`/`-ai-e2e`）、监盘（`-monitor`）、浮窗（`-float`）、分栏缩放（`-resize`）、自选+详情+搜索（`visual-test`）。
- **现有 spec 未覆盖 / 只带过未断言**：① 盘口五档视觉内容（#11）；② 回测**结果曲线**（#9）；③ 预警页（#18）；④ 设置页（#19）；⑤ 回测页/沪深列表完整视觉（#15/#16）；⑥ 指数栏（#13）。

## 5. 执行建议

1. **改 UI 后的最低要求**：跑受影响界面 + P0 全过（P0 是最容易渲染坏且 DOM 测不出的部分）。
2. **流程**：`npm run build:win` → 跑相关 `scripts/*.spec.js` → 把 `test-results/` 里对应截图逐个喂 zhipu-vision，按上表"识别重点"核对。
3. **识别输出含糊/自相矛盾时**，回到像素级断言二次确认（`visual-test-drawing.spec.js` 已有 `getImageData` 统计白线/区域 diff/黄色填充等手段）。
4. 每个 spec 运行前先确认环境变量：真实 LLM 用例需 `LOCALSTOCK_DS_KEY`（`-ai-e2e` / `-monitor`）；纯渲染验证不需要。
5. 截图建议**最大化窗口**，避免视口/滚动遮挡；持久化状态（localStorage 分栏宽度、settings）会让断言必须"相对变化"而非绝对值。
