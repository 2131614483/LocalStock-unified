## 2026-08-27 · 算法画线"看不到"：dataZoom filterMode 滤掉窗外画线数据点

### 现象
算法画线引擎运行成功（返回 3 条画线、入库数量 +3），K 线图 canvas 上却一条都看不到（像素扫描红/绿/蓝目标色横线均为 0 行）；手动画线有时也不可见。

### 根因
ECharts `dataZoom` 默认 `filterMode: 'filter'`：**把可视窗口外的数据点从系列里过滤掉**。算法画线的锚点常在窗口外（如 `draw_hline` 锚点 x=0、趋势线端点 x=0/n-1、用户放大到局部时线的远端），custom series 的数据点被滤掉后 **renderItem 根本不被调用** → 画线整个消失。日 K 默认只显示最后 120 根（3843 根数据 zoomStart≈97%），算法画线天然全画在窗外，必现。

### 修复（KLineChart.tsx）
两个 dataZoom（inside + slider）都加 `filterMode: 'none'`：保留全部数据点、仅按缩放换算坐标。画线 renderItem 始终被调用，横线/线段正确横贯可视区并随缩放平移。

### 验证
- 像素扫描：修复前红/绿/蓝目标色横线 0 行；修复后截图肉眼可见压力/支撑横线。
- E2E：AI 生成画线代码 → 运行 → 画线数 1→3，截图确认红/绿横线上屏。

### 反思
- **ECharts custom series + dataZoom 的默认 filterMode 是隐形杀手**：数据"在但没画"时先查 filterMode，再查坐标转换（另一个坑：category 轴 coord 要传类别值）。
- 排查链路要分段取证：引擎输出（正常）→ 入库（正常）→ option series（存在）→ **canvas 像素（异常）**，四段定位到渲染层；再由"数据点在窗外"联想到 filterMode。

## 2026-08-27 · 推理模型（qwen3.5 等）输出带 <think> 段 → JSON 提取失败

### 现象
本地 Ollama qwen3 系列模型返回的结构化 JSON 解析偶发失败（"AI 输出非 JSON"）。

### 根因
推理模型经 OpenAI 兼容端点输出前带 `<think>…</think>` 思考段；未闭合截断时更棘手。extractJson 直接找 `{...}` 平衡段可能命中 think 里的花括号。

### 修复（monitor/predict.ts extractJson）
提取前先剥 `<think>…</think>`（含未闭合截断的处理）再走原有"直接解析 → 平衡段截取"两级逻辑。所有走 callPredictApi 的 AI 功能（监盘预测/分时预测/画线代码）一并受益。

### 反思
接推理模型时，**结构化输出解析要先做 think 段清洗**；用严格提示词 + 鲁棒提取而非 response_format（推理模型的 reasoning 吃 token，json_object 反而更慢更贵）。

## 2026-08-26 · Chromium 里 `thead th` sticky 吸顶的三个隐藏失效条件

### 现象
- 表格表头 `thead th { position: sticky; top: 0 }` + 外层滚动容器 `.table-scroll { overflow-y: auto }`，computed style 显示 `position: sticky` 正确，但滚动时表头照样随内容滚走（表头相对滚动容器顶部偏移 = -scrollTop）。
- 同样的 HTML 结构在最小复现页里 sticky 正常；同一表格 `cloneNode` 到普通 div 里也正常——只有 React 渲染的原件失效。

### 根因（三个条件叠加，逐个消融实验定位）
1. **`border-collapse: collapse`**：使 `th` sticky 完全失效（经典坑）。
2. **滚动容器是 flex item 且 `flex: 1`**（flex-basis: 0%）：sticky 失效；`min-height: 0` 无辜。卡片改 grid `auto 1fr auto` 绕过。
3. **滚动容器的直接子元素是 `<table>`**（最隐蔽）：sticky 失效，computed style 全对但不吸附。把 table 包进一层普通 `<div>` 立即恢复。Chromium 对"滚动容器直接子元素为 table"的 sticky containing block 计算有缺陷。

### 修复（`StockTable.tsx` + `globals.css`）
- `border-collapse: separate; border-spacing: 0`（单元格只有 border-bottom，视觉与 collapse 无差）。
- `.table-card` 从 flex 改 `display: grid; grid-template-rows: auto 1fr auto`，`.table-scroll` 只留 `overflow-y: auto; min-height: 0`（不用 flex:1）。
- `StockTable` 内部把 `<table>` 包进 `.table-scroll > div`（滚动区垫一层普通 div）。

### 验证
- Playwright 探针（`scripts/p0-verify.spec.js`）：压缩卡片高度 → 滚动 27px → 断言表头 y 不变（修复前 y 随滚动移动 27px，修复后不变）。
- 逐属性消融法：在真实页面里逐个改样式（overflow/flex/min-height/包裹 div）+ 每步验证 scrollTop 确实变了，一次锁定真凶。注意早期实验有假阳性：断言前必须确认滚动真的发生了。

### 反思
- **computed style 正确 ≠ sticky 生效**：sticky 是布局期行为，只能用几何断言（getBoundingClientRect 相对滚动容器）验证。
- **克隆/最小复现正常不代表原件正常**：本次差异点恰恰在"滚动容器直接子元素是 table"这种结构细节上，克隆到普通 div 反而掩盖了它。消融实验要在**原地真实结构**上做。
- `.splitpane-item > * { height: 100% !important }` 会盖掉内联 height，调试布局时别被它骗。

## 2026-08-26 · P1 批次三坑：渲染层 import electron 白屏 / Playwright 焦点吞 mousedown / SplitPane 轴读反

### 1. 渲染层 import 'electron' → `__dirname is not defined` 白屏
- **现象**：全局缩放最初写在渲染层 `src/lib/zoom.ts`（`import { webFrame } from 'electron'`），打包后启动白屏，控制台 `Uncaught ReferenceError: __dirname is not defined`。
- **根因**：渲染层是 ESM bundle，`import 'electron'` 会把**整个 electron npm 包**（含 get-electron-path 等 node 代码）拖进 bundle，其内部 `__dirname` 在浏览器上下文不存在。
- **修复**：缩放逻辑整体移到 **preload**（webFrame + window 事件监听都在 preload 可用，`ipcRenderer.invoke('settings:*')` 也在手边）。
- **反思**：渲染层永远不 import 'electron'；需要 electron 能力就进 preload 或走 IPC。

### 2. Playwright 启动后窗口不在前台 → Windows 吞 mouse down（误判为 titleBarStyle bug）
- **现象**：加深色标题栏（titleBarStyle:'hidden'）后画线拖拽失效。A/B 实验混乱：去掉 overlay 恢复、去掉 hidden 恢复、恢复后又丢——结论反复横跳。
- **根因**：**Playwright `_electron.launch` 启动的窗口不在前台时，Windows 把 mouse down 路由给前台窗口**（mousemove 却正常广播）。与 titleBarStyle 完全无关。之前时好时坏 = 焦点随机。
- **定位**：focus 对照实验——同一构建 `w.show()+w.focus()` 后 mousedown 立即恢复。
- **修复**：所有依赖真实鼠标拖拽的测试启动后先 focus；visual-test 加统一 focus 步骤。
- **反思**：桌面 UI 自动化里**窗口焦点是一等变量**；A/B 实验前先控制焦点，否则结论全是噪声。

### 3. SplitPane 方向轴读反 + 钳制值回写卡死
- **轴读反**：`direction='vertical'` 是**竖分隔条**（调列宽），钳制应读 `clientWidth`，曾读成 `clientHeight` → 监盘窗按高度钳宽度，拖 800 被钳成 291（高度 cap）。
- **钳制回写**：钳制后的生效值若回写 localStorage，小窗口的临时钳制值会永久卡死布局（最大化不恢复）。修复：**userSize（用户值，持久化）/ size（生效值，clamp）两层分离**——小窗临时钳小、大窗自动恢复用户值。
- **验证**：探针跑完整周期：拖 800 → 缩窗钳 770 → 最大化恢复 800。

### 附：titleBarOverlay 在 Windows 的真问题
`titleBarOverlay`（系统绘制按钮）虽不吞 mousedown，但与自绘按钮二选一；项目选了 `titleBarStyle:'hidden'` + 自绘 `TitleBarControls`（`win:minimize/maximizeToggle/close` IPC，`BrowserWindow.fromWebContents(e.sender)` 定位发起窗口，主窗/浮窗/监盘窗通用）。

## 2026-08-13 · 数据包缺 `sync_meta` 表 → 回测页误报"行情库未就绪"

### 现象
- 视觉验证轮：回测页顶部横幅显示「**回测行情库未就绪 · 未检测到数据**」，但点「▶ 运行回测」能正常跑出结果（32 笔交易 / 243 条日记录 / 基准收益）。
- 自相矛盾：`getDataStatus()` 返回 `exists:false`，回测引擎却读到了同一份数据。

### 根因
- `electron/backtest.ts` 的 `getDataStatus()` 在 `SELECT COUNT(*) FROM stocks/stock_daily` 之后**无条件**查询 `sync_meta` 表取 `db_version` / `last_full_sync`。
- 发布的 `LocalStock-data-0.2.0.zip` 里的 `stock_data.db`（3.1GB，2026-08-10 打包）**缺 `sync_meta` 表**（该表由 `download_full_data.py` 全量下载时写入，此数据包疑似由旧脚本或未跑全量的流程产出）。
- 查询抛 `SqliteError: no such table: sync_meta` → 被外层 `catch` 吞掉 → 返回 `{exists:false, error}` → `DataDownloadPanel` 只读 `dataStatus.exists`，误显示"未就绪"，error 被隐藏。

### 修复
- `getDataStatus()` 把 `sync_meta` 查询**单独包一层 try/catch**：表缺失时降级为"数据可用，仅无版本/同步时间"，不再因一张元数据表误报整个库未就绪。
- 核心表（`stocks` / `stock_daily`）仍在外层 try——它们缺失才真正算未就绪，语义正确。

### 验证
- `npm run typecheck` 通过。
- 重建打包产物后实测：`getDataStatus()` 返回 `{"exists":true,"stocksCount":5206,"dailyRows":16486235,"dateFrom":"1990-12-19","dateTo":"2026-08-10"}`；回测页横幅显示「✓ 行情库已就绪 · 5206 只股票 · 16,486,235 行日线 · 1990-12-19 ~ 2026-08-10」，回测仍正常。
- 注：`npm run build:win` 的 portable 单文件目标因沙箱拦截联网下载 winCodeSign 而失败，但 `dist/win-unpacked`（视觉测试直接启动的产物）已更新并通过验证。

### 反思
- **别把元数据查询和核心数据查询放进同一个 try**：元数据表缺失 ≠ 数据不可用。凡是"可选"信息（版本、时间戳、缓存元数据）都应独立容错。
- `DataDownloadPanel` 只读 `dataStatus.exists`，把 `error` 字段吞了，诊断时信息丢失。可考虑把 error 展示出来（至少 console 输出），别让"未就绪"变成无解释的红字。
- 测试只覆盖了 `exists:false` 分支的渲染，没在真实数据上断言 `exists:true` 分支——正是视觉验证才暴露这条。可补：有真实行情库时横幅应显示"已就绪"。

## 2026-08-13 · 视觉测试两个误报（测试层问题，非产品 bug）

### 1. 画线管理"取消勾选隐藏"断言阈值过紧

- **现象**：`visual-test-drawing.spec.js`「画线管理」用例失败：取消勾选后 `whiteVisible()=2967` > 预期 `基线+200=2899`。
- **根因**：隐藏功能实际正常——探针实测 画线 5628 → 取消勾选 2542（回落到基线 2306 附近）；残差 +236~268 是画线移除后图表重绘的抗锯齿噪声，断言阈值 `baseline+200` 过紧。
- **修复**：隐藏判定阈值 `baseline+200` → `baseline+400`（仍远低于"可见"的 `baseline+500`，不会混淆）。
- **反思**：像素级断言要和"基线 + 重绘噪声"比，而不是和纯基线比；阈值要给噪声留余量，否则测的是噪声而非功能。

### 2. 回测结果图表选择器用错类名

- **现象**：补盲 spec（`visual-test-aux.spec.js`）断言 `.backtest-result .chart-box canvas` 找不到 → 一度以为收益/回撤曲线没渲染。
- **根因**：`ResizableChartShell` 把 ECharts 容器渲染成 `chart-box-sm`（`KLineChart` 用的是 `chart-box`），选择器写错。像素探针确认 `.chart-box-sm canvas` = 2 且内容非空（收益图非背景像素 3399、回撤图 59568）。
- **修复**：aux spec 选择器 `.chart-box` → `.chart-box-sm`。
- **反思**：ECharts 容器类名不统一（`chart-box` vs `chart-box-sm`），断言前先确认组件实际渲染的类名，别凭印象。

## 2026-08-13 · 验证流程经验

- **Playwright 每次运行清空 `test-results/`**：上一轮截图会被冲掉（本次首轮截图因此丢失，重新归档才保住）。解决：跑测试加 `--output=test-artifacts`，把 Playwright 自己的产物目录挪开，测试里 `win.screenshot()` 写的 `test-results/` 才得以留存。
- **`win.screenshot()` 默认只拍视口**（`fullPage:false`）：回测结果图在指标卡下方，视口截图看不到曲线，导致智谱误判"未渲染曲线"。用 `scrollIntoViewIfNeeded` + `clip`，或 `fullPage:true` 再截。
- **智谱识图会把中式"红涨绿跌"判为异常**：负涨幅显示绿色它报"着色不符"。prompt 里需明确说明本项目采用红涨绿跌，再让其核对。
- **截图时机要等数据就绪**：`01-watchlist` 在行情推送前截到"暂无数据"空态，被误读为 bug。断言/截图前先等数据或轮询。
