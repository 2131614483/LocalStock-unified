# 本地化智能股票看盘与分析系统 — 详细设计说明书

> 版本 v1.0 ｜ 目标平台：Windows / macOS（本地运行，无云依赖）｜ 目标用户：职业日内交易者、策略回测研究员

## 1. 技术栈选型

### 1.1 候选方案对比

| 维度 | **PyQt5 + PyQtGraph（方案A）** | Electron + Vue3（方案B） |
|---|---|---|
| **内存占用（基准）** | 常驻 ~120–180MB（Qt 原生控件） | 常驻 ~300–500MB（Chromium 多进程，每窗口 +~100MB） |
| **绘图性能** | PyQtGraph 基于 Qt GraphicsView + OpenGL，万级数据点流畅（分钟线全量 >2万点无压力） | ECharts/Canvas 在 WebView 中渲染，数据量大时受 GPU 合成与 JS GC 影响 |
| **本地计算层** | Python 直接内嵌（Pandas/Numpy 同进程或子线程），无跨进程序列化开销 | 计算在 Node/渲染进程，Python 指标需子进程 + JSON 序列化，IPC 有损耗 |
| **实时性/低延迟** | 原生事件循环，绘图与预警同进程，延迟最低 | WebView 事件循环 + IPC，延迟略高 |
| **打包体积** | PyInstaller ~60–120MB（含 Qt） | electron-builder ~150–250MB（含 Chromium） |
| **界面美观度** | 需用 QSS 定制，可达到专业看盘风格（暗色主题） | Web 技术栈，UI 表现力强、生态丰富 |

### 1.2 结论：**选 PyQt5 + PyQtGraph**

**理由（对应本项目三个硬约束）：**
1. **内存控制**：需求要求连续运行 8 小时泄漏 <500MB、常驻内存可控。Electron 单 Chromium 进程基线就 300MB+，叠加 50 只自选 + 图表后贴近红线；PyQt5 基线 ~150MB，余量大。
2. **绘图性能**：核心是"K线多周期切换重绘 <200ms"。PyQtGraph 用 GraphicsView + OpenGL 渲染，**数据点数量不构成瓶颈**（1 分钟线 3 年约 4.3 万点可整体缓存重绘）；Matplotlib 定位为**离线分析**（导出图表），不作为实时绘图路径。
3. **计算与 UI 同栈**：MACD/KDJ/BOLL 用 Pandas 向量化计算，与 UI 同进程（子线程）直接传结果，无序列化；预警判定与绘图在同一事件循环内，延迟最低。

**何时才选 Electron**：需要复杂 Web 前端交互（富文本、拖拽式公式编辑器、第三方前端库）且能接受内存开销时。本项目以"高性能本地绘图 + 低延迟"为第一目标，故选 PyQt。

## 2. 系统整体架构（数据流向）

```
┌────────────┐   ┌──────────────┐   ┌────────────┐   ┌───────────────┐   ┌──────────────┐
│  数据源层    │ → │  数据适配层    │ → │  本地缓存层  │ → │   业务计算层    │ → │   UI 渲染层   │
│ 新浪/腾讯   │   │ HTTP 客户端    │   │ SQLite 表   │   │ 指标(MA/MACD/  │   │ 主窗口/QThread │
│ AKShare     │   │ 解析/重试/降级 │   │ + 内存 cache│   │ KDJ/BOLL/预警) │   │ PyQtGraph 图  │
│ 东财(备用)   │   │ 交易日历对齐   │   │ Redis(可选) │   │ (Pandas 向量化) │   │ 自选表/弹窗/WAV│
└────────────┘   └──────────────┘   └────────────┘   └───────────────┘   └──────────────┘
```

**分层职责：**
- **数据源层**：实时快照（新浪 `hq.sinajs.cn`、腾讯 `qt.gtimg.cn`）、历史（AKShare 新浪/东财源）。多源冗余。
- **数据适配层**：统一字段映射（时间戳/价格/量额），交易日历对齐（沪深 9:30-11:30、13:00-15:00；港股 9:30-12:00、13:00-16:00；美股 21:30-4:00 冬令时），断连重试/降级。
- **本地缓存层**：SQLite 持久化（日线/分钟线/自选/预警）+ 内存字典缓存今日实时分笔（可选 Redis 持久化当日 tick）。
- **业务计算层**：Pandas 向量化指标（`rolling().mean()`、`ewm()`），预警条件判定（均线突破/MACD金叉/量能放大）。
- **UI 渲染层**：只做绘制。所有网络 I/O 与重计算放 `QThread` Worker，结果经 `pyqtSignal` 回到主线程。

### 3.2 索引与"时间分区"方案

```sql
-- 联合索引：日线按 (ts_code, trade_date) 排序，命中 ts_code 前缀即走索引
CREATE INDEX IF NOT EXISTS idx_daily_kline ON daily_kline(ts_code, trade_date);
CREATE INDEX IF NOT EXISTS idx_minute_kline ON minute_kline(ts_code, period, trade_time);
CREATE INDEX IF NOT EXISTS idx_daily_date    ON daily_kline(trade_date);   -- 全市场某日扫描
```

**关于"按时间分区"**：**SQLite 不支持 MySQL/PostgreSQL 的 RANGE 分区**。给出三种替代方案：

- **方案一（推荐）：单表 + 复合主键/索引**。`PRIMARY KEY (ts_code, trade_date)` 即按 ts_code 聚簇，单只股票读取是顺序扫描该股票区间，百万行内毫秒级。日线 3 年 ≈ 750 行/股 × 5000 股 ≈ 375 万行，单表完全可承受。
- **方案二（大数据量才需要）：按年分表**。`daily_kline_2024` / `daily_kline_2025`，通过视图 `CREATE VIEW daily_kline AS SELECT ... FROM daily_kline_2025 UNION ALL ...` 屏蔽分表。适合分钟线全量（3 年 1 分钟 ≈ 4300 万行）时把单表拆小，便于按年删除过期数据。
- **方案三：PRAGMA 优化**。建表后 `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;` 减少写盘锁等待，配合 `INSERT OR IGNORE` 断点续传。

> 分钟线 3 年全量体量大，建议用方案二（按年分表）+ WAL。

## 4. 核心类设计与多线程防卡顿

### 4.1 线程模型

```
┌───────────────────────────── Main Thread (UI) ─────────────────────────────┐
│ MainWindow / KLineWidget / WatchlistTable / AlertManager / 弹窗 / 播放WAV   │
│ 只做：接收 signal → 更新控件、重绘 PyQtGraph                              │
└───────────────▲──────────────────────────────▲────────────────────────────┘
                │ result_ready(emit)            │ progress(emit)
┌───────────────┴──────────────────────────────┴────────────────────────────┐
│ QThread Worker（数据下载）      │ QThreadPool（指标计算）                   │
│ fetch_realtime_quote()         │ calc_ma/calc_macd/calc_kdj (Pandas)      │
│ download_history()             │ alert_scan()                             │
│ 断连重试/降级                   │ 防重复计算（同一 ts_code 只一个任务）       │
└────────────────────────────────────────────────────────────────────────────┘
```

**原则：**
- 网络 I/O（行情拉取、历史下载）→ **独立 QThread Worker**，不阻塞 UI。
- CPU 密集（指标向量化、预警扫描）→ **QThreadPool（全局线程池）**，单任务短、可并行多只股票。
- UI 只收 `pyqtSignal`；任何耗时计算严禁出现在主线程槽函数内。

### 4.2 QThread + pyqtSignal 伪代码（MACD 从子线程发到主线程）

```python
from PyQt5.QtCore import QThread, pyqtSignal
from PyQt5.QtWidgets import QWidget, QVBoxLayout
import pyqtgraph as pg
import pandas as pd

# ---------- 计算 Worker（QThread）----------
class MACDWorker(QThread):
    result_ready = pyqtSignal(object, object)   # (dates: list, macd_values: list)
    def __init__(self, df: pd.DataFrame):
        super().__init__()
        self.df = df
    def run(self):
        # 在子线程做 Pandas 向量化计算，主线程不阻塞
        close = self.df['close']
        ema12 = close.ewm(span=12, adjust=False).mean()
        ema26 = close.ewm(span=26, adjust=False).mean()
        dif  = ema12 - ema26
        dea  = dif.ewm(span=9, adjust=False).mean()
        macd = (dif - dea) * 2
        dates = self.df['trade_date'].tolist()
        values = [dif.tolist(), dea.tolist(), macd.tolist()]
        self.result_ready.emit(dates, values)   # 发回主线程

# ---------- 图表控件（Main Thread）----------
class KLineWidget(QWidget):
    def __init__(self):
        super().__init__()
        self.plot = pg.PlotWidget()   # PyQtGraph 高性能图
        self.worker = None
    def on_stock_selected(self, ts_code: str):
        # 切换股票 → 后台起 worker 算指标，避免界面卡死
        df = load_daily_from_sqlite(ts_code)          # 本地读，快
        self.worker = MACDWorker(df)
        self.worker.result_ready.connect(self.on_macd_ready)
        self.worker.start()                            # 立即返回，UI 不阻塞
    @pyqtSlot(object, object)
    def on_macd_ready(self, dates, values):
        # 回到主线程绘图
        dif, dea, macd = values
        self.plot.clear()
        self.plot.plot(dates, dif, pen='w')           # DIF
        self.plot.plot(dates, dea, pen='y')           # DEA
        macd_bar = pg.BarGraphItem(x=range(len(macd)), height=macd, width=0.6)
        self.plot.addItem(macd_bar)                    # MACD 柱
        self.plot.enableAutoRange('y')
```

**要点：**
- `worker.start()` 后主线程立即返回，拖动/切换不卡。
- `result_ready` 是 **QueuedConnection**（跨线程自动），槽函数在**主线程**执行，PyQtGraph 必须在主线程操作。
- 切换股票时先 `self.worker.requestInterruption()` 或在 `run()` 内定期检查 `isInterruptionRequested()` 放弃旧计算，避免慢任务堆积。

### 5.2 指标计算接口（Pandas 向量化）

```python
def calc_ma(data: pd.DataFrame, period: int) -> pd.Series:
    """
    计算简单移动平均。
    data: 需含 'close' 列（按 trade_date 升序）。
    返回：与 data 等长 Series，前 period-1 个为 NaN。
    实现：data['close'].rolling(window=period, min_periods=period).mean()
    """
    return data['close'].rolling(window=period, min_periods=period).mean()

def calc_boll(data: pd.DataFrame, period: int = 20, k: float = 2.0) -> pd.DataFrame:
    mid = calc_ma(data, period)
    std = data['close'].rolling(period).std(ddof=0)
    return pd.DataFrame({'upper': mid + k*std, 'mid': mid, 'lower': mid - k*std})

def calc_macd(data: pd.DataFrame, fast=12, slow=26, signal=9) -> pd.DataFrame:
    ema_f = data['close'].ewm(span=fast, adjust=False).mean()
    ema_s = data['close'].ewm(span=slow, adjust=False).mean()
    dif = ema_f - ema_s
    dea = dif.ewm(span=signal, adjust=False).mean()
    return pd.DataFrame({'dif': dif, 'dea': dea, 'macd': (dif - dea) * 2})

def calc_kdj(data: pd.DataFrame, n=9, m1=3, m2=3) -> pd.DataFrame:
    low_n = data['low'].rolling(n, min_periods=1).min()
    high_n = data['high'].rolling(n, min_periods=1).max()
    rsv = (data['close'] - low_n) / (high_n - low_n).replace(0, 1e-9) * 100
    k = rsv.ewm(alpha=1/m1, adjust=False).mean()
    d = k.ewm(alpha=1/m2, adjust=False).mean()
    return pd.DataFrame({'k': k, 'd': d, 'j': 3*k - 2*d})

def calc_rsi(data: pd.DataFrame, period: int = 14) -> pd.Series:
    delta = data['close'].diff()
    gain = delta.clip(lower=0).rolling(period).mean()
    loss = (-delta.clip(upper=0)).rolling(period).mean()
    rs = gain / loss.replace(0, 1e-9)
    return 100 - 100 / (1 + rs)
```

> 所有指标返回 `pd.DataFrame/Series`，用 `to_numpy()` 转后经 `pyqtSignal` 传 UI，避免跨线程传 DataFrame。

## 6. 数据源方案（最关键）

### 6.1 实时行情（免费稳定，多源冗余）

| 源 | 接口 | 覆盖 | 说明 |
|---|---|---|---|
| **腾讯** | `https://qt.gtimg.cn/q=sh600519,sz000858` | 沪深、港股 | 文本 `~` 分隔，含五档/涨跌停，**GBK 编码需解码**；快、稳定 |
| **新浪** | `https://hq.sinajs.cn/list=sh600519` | 沪深、港股、美股 | 需 `Referer: finance.sina.com.cn`；美股实时 |
| **AKShare** | `ak.stock_zh_a_spot_em` 等 | 全覆盖 | 综合源，适合兜底/历史 |
| **东财** | `push2.eastmoney.com/...` | 沪深 | 高频限流，作**备用** |

**断连重试机制（数据适配层内置）：**
```python
def _request_with_retry(url, headers, retries=3, timeout=3.0):
    for i in range(retries):
        try:
            r = requests.get(url, headers=headers, timeout=timeout)
            if r.ok: return r.text
        except (requests.Timeout, requests.ConnectionError):
            pass
        time.sleep(0.5 * (i + 1))          # 指数退避
    return None
```
- 主源失败 → 按源优先级表自动降级（腾讯→新浪→AKShare）。
- 早盘 9:30 拥堵：超时 3s → 重试 3 次 → 降级；同一秒内**合并请求**（批量代码一次拉，不逐只请求）。
- 每次请求间隔 ≥ 200ms（全局节流器），避免被免费源封 IP。

### 6.2 历史数据批量补全（首装近 3 年）

- **日线**：AKShare `ak.stock_zh_a_hist(symbol, period='daily', adjust='qfq')`，按 `sync_state.last_date` 增量 `INSERT OR IGNORE`；断点续传。
- **分钟线**：免费源**历史 1 分钟深度有限**（新浪仅近约 5 天、东财被限流）。给出分级策略：
  1. **近 5 个交易日**：新浪 `getKLineData?scale=1`（1 分钟）实时补齐；
  2. **更早历史**：用 **5/30 分钟线**（AKShare 新浪 `scale=5/30`，历史更深）回填，满足大多数日内策略；
  3. 若要全量 3 年 1 分钟：推荐用户安装通达信客户端读本地 `.lc1` 文件（能下多少下多少），或接入 Tushare 积分接口。
- **批量执行**：`Worker` 线程按股票队列串行下载，进度 `pyqtSignal` 报给 UI（进度条），可暂停/续传，失败股票重试 3 次后跳过记录到日志。

### 7.2 场景 B：快速拖动 K 线缩放连续触发绘图 → 防抖（Debounce）

```python
class KLineWidget:
    def __init__(self):
        self._debounce = QTimer(self)
        self._debounce.setSingleShot(True)
        self._debounce.setInterval(150)          # 150ms 防抖窗口
        self._debounce.timeout.connect(self._do_redraw)

    # 视图范围变化（拖动/滚轮/缩放）频繁触发
    def on_view_range_changed(self, *args):
        self._debounce.start()                    # 重置 150ms 计时

    def _do_redraw(self):
        # 仅在用户停止拖动 150ms 后执行一次真正的重绘
        start = time.perf_counter()
        self.plot.setXRange(self._view_range(), padding=0)
        self.plot.setYRange(self._auto_yrange())   # 按可见区间算 Y
        log.debug(f'redraw {time.perf_counter()-start:.0f}ms')
```
- 配合 PyQtGraph 的 `sigRangeChangedManually`，连续缩放只重绘最后一次。
- 分钟线大数据重绘时，先在 Worker 做**可见区切片**（只把屏幕内 ~800 根传给绘图），全量缓存于内存字典，切换区间再取，保证 <200ms。

---

## 8. 性能指标与保障

| 指标 | 目标 | 实现手段 |
|---|---|---|
| 日 K 切换周期重绘 | **< 200ms** | PyQtGraph OpenGL + 可见区切片（屏幕 ~800 根）+ 防抖 150ms + 全量缓存于内存字典 |
| 50 只自选实时刷新 | 1s 内全部更新 | 批量接口（一次请求 50 代码）+ 增量 dict 更新表项，不整表重绘 |
| 连续 8h 内存泄漏 | **< 500MB** | 对象复用（图表 item 复用）、`weakref`、Worker 完成后 `deleteLater`、指标结果用 `to_numpy()` 减少对象、定期 `gc.collect()` |
| 预警响应 | < 1s | 指标计算 QThreadPool 并行；预警扫描每 tick 一次，命中才 emit |

## 9. 打包与部署（无需 Python 环境的单文件）

**推荐 PyInstaller（简单）**：

```bash
pip install pyinstaller
pyinstaller --noconfirm --onefile --windowed \
  --name LocalStock \
  --icon app.ico \
  --hidden-import pyqtgraph \
  --collect-submodules PyQt5 \
  app/main.py
```
产物：`dist/LocalStock.exe`（约 60–120MB），双击即用，无需安装 Python。

**备选 Nuitka（体积更小、性能更优、启动更快）**：

```bash
pip install nuitka ordered-set
python -m nuitka --onefile --windows-disable-console \
  --include-package=pyqtgraph --include-package-data=PyQt5 \
  --output-dir=build app/main.py
```
产物：`build/LocalStock.exe`（约 40–80MB），原生编译。

**数据文件说明**：
- SQLite 库（`data/stock.db`）与 exe 同级目录存放，用户数据独立于程序（升级程序不丢数据）。
- `data/` 目录首启自动创建；WAV 预警音放 `assets/alerts/*.wav`。
- macOS 打包同理（`--windowed` → `.app`，或用 `py2app`）。
